# 同步觀影 watch-sync

和朋友各自用自己的帳號，同時看同一部影片：播放、暫停、拖進度都會同步，其中一人選了新影片，另一人的瀏覽器會自動跳到同一部。

## 支援平台

| 平台 | 電腦（Chrome） | iPhone / iPad |
|---|---|---|
| 愛奇藝（iqiyi.com、iq.com） | 支援 | 支援（Safari + Userscripts 腳本） |
| YouTube | 支援（`/watch` 頁面） | 支援（伺服器附的網頁版，貼 YouTube 網址） |
| Netflix | 支援（`/watch` 頁面） | 不支援 |
| Android | 目前沒有支援的方案 | — |

電腦、iPhone、iPad 可以同一個房間混用，人數不限。

## 運作原理

```
你的瀏覽器 ──┐
             ├──  WebSocket 伺服器（server/）  ──┤
朋友的瀏覽器 ─┘      依「房間代碼」轉發訊息
```

每個人播放的仍然是自己帳號、從平台載入的影片。程式只做兩件事：

1. 監聽你的播放、暫停、拖進度，把「動作 + 目前秒數」傳給同房間的人。
2. 收到別人的動作後，在自己的播放器上做同樣的操作。

## 1. 架設伺服器（只需要一個人做）

### 方案 A：部署到 Render（推薦，網址固定）

1. 把這個專案放上 GitHub。
2. 到 https://render.com 登入，New → Web Service，選你的 repo。
3. 設定：
   - Root Directory：`server`
   - Build Command：`npm ci`
   - Start Command：`npm start`
   - Instance Type：Free
4. 部署完成後會得到 `https://你的服務.onrender.com`，把 `https` 改成 `wss`，就是**伺服器網址**：
   ```
   wss://你的服務.onrender.com
   ```

注意：Render 免費方案閒置一段時間會休眠，第一次連線要等 30～50 秒喚醒。想暫時停掉服務，可以在服務頁面選 Suspend，要用時再 Resume，網址不會變。

### 方案 B：自己的電腦 + cloudflared（臨時用）

```powershell
cd server
npm install
npm start
```

另開一個視窗：

```powershell
cloudflared tunnel --url http://localhost:8080
```

會得到 `https://xxxx.trycloudflare.com`，改成 `wss://xxxx.trycloudflare.com` 當伺服器網址。

這個方案的缺點：網址**每次重開都會換**，要重新告訴朋友並重新設定；免費通道也可能不穩定（會出現 503）。自己一個人在同一台電腦測試時，可以直接用 `ws://localhost:8080`。

> Windows PowerShell 5.1 不支援 `&&`，指令請分行執行。

## 2. 電腦：安裝 Chrome 擴充套件（每個人都要）

需要 Chrome 111 以上。

1. 打開 `chrome://extensions`，開啟右上角「開發人員模式」。
2. 按「載入未封裝項目」，選 `extension` 資料夾。
3. 點擴充套件圖示，填：
   - **伺服器網址**：`wss://...`
   - **房間代碼**：所有人填一樣的
4. 按「儲存並連線」。
5. 各自打開同一部影片。YouTube、Netflix 要在 `/watch` 頁面；愛奇藝在播放頁。

> 擴充套件只會在頁面載入時注入。**安裝完或第一次設定後，要重新整理影片頁**，之後改設定則不需要。

> 擴充套件 ID 固定為 **`lkfcgbmfbfadebnadmochcppblfhoijm`**（`manifest.json` 裡的 `key` 決定，不管放在哪個資料夾都一樣），伺服器可以用它限制只有這個擴充套件能連線。

### 左上角狀態標籤

| 顏色 / 文字 | 意思 |
|---|---|
| 紅「尚未設定伺服器/房間」 | 回擴充套件圖示填設定 |
| 紅「連線中…」「連線失敗」「斷線，重連中…」 | 網址錯誤、伺服器休眠或不穩，見下方疑難排解 |
| 紅「已連線，等朋友加入」 | 你連上了，對方還沒進同一個房間 |
| 綠「已連線（房內 N 人）」 | 正常，可以同步 |

### 快捷鍵

- **Alt+S**：把我現在的進度推給對方（覺得兩邊差了幾秒時使用）。

## 3. iPhone / iPad

### 3-1 看愛奇藝：Safari + Userscripts 腳本

1. App Store 安裝免費的 **Userscripts**（需要 iOS 15 以上）。
2. 設定 → Safari → 擴充功能 → Userscripts：開啟，權限設成「所有網站：允許」。
3. 把 `ios/watch-sync-iqiyi.user.js` 傳到手機（AirDrop、iCloud，或用 LINE 傳給自己再存進「檔案」），放進 Userscripts 的資料夾（「檔案」App → 我的 iPhone → Userscripts）。檔名必須以 `.user.js` 結尾。
4. 用 **Safari** 打開愛奇藝網頁版（愛奇藝 App 不行），重新整理。
5. 第一次會跳出輸入框，填伺服器網址與房間代碼。

左上角兩個按鈕：

- 點狀態文字：修改伺服器網址 / 房間代碼。
- 點「↻」：把我的進度推給對方（等於電腦的 Alt+S）。

如果 iPhone 上的愛奇藝版面不一樣或一直要你開 App，可以在 Safari 的「AA」選單選「要求電腦版網站」再重新整理。

### 3-2 看 YouTube：網頁版

1. Safari 開 `https://你的服務.onrender.com`。
2. 填房間代碼、貼上 YouTube 網址，按「進入房間並載入影片」。
3. 之後想換影片，貼新網址再按一次，就會推給對方。「推送我的進度給對方」可以手動對齊進度。

### iOS 的共通限制

- **iOS 擋自動播放**：被遠端按播放時可能先被擋住。腳本版會顯示「點一下頁面即可加入同步」，點一下就行；網頁版則是第一次要自己點一下播放。
- **鎖屏或切到別的 App 一陣子，連線會被 iOS 中斷**，回到畫面後會自動重連，再按「↻」或請對方按 Alt+S 對齊。
- 愛奇藝請用 Safari 網頁版，App 內的播放器抓不到。

## 自動跳轉

- 任何人在愛奇藝 / YouTube / Netflix 選了新影片，同房間的人會自動跳到同一部。
- 新朋友加入房間時，原本在房裡的人會把目前的影片推給他。
- 剛加入、跟著對方跳到新影片、或在同一部影片重新整理的人，會自動向對方要目前進度並跳過去（電腦、iPhone 腳本都支援）。
- 換頁、重新整理不算「新加入」：同一個人 10 秒內重新連上，對方不會把影片推過來，所以在同網站找新影片時不會被拉回去；自己點進新影片時，對方會跟過來。
- 對方要跳轉成功，他必須已經在**同一個網站**上（首頁也可以，不一定要在播放頁）；只允許同網站之間的跳轉，不會被導去別處。
- iPhone 腳本有防迴圈保護：同一個網址 30 秒內只會自動跳一次。

## 疑難排解

| 現象 | 原因與做法 |
|---|---|
| 完全沒有左上角標籤 | 擴充套件是在頁面開著之後才安裝 / 更新的：到 `chrome://extensions` 重新載入，再 F5。iOS 則確認 Userscripts 已啟用該腳本並重新整理。 |
| 紅色「尚未設定伺服器/房間」 | 設定是空的，到擴充套件圖示重新填（移除重裝擴充套件會清掉設定）。 |
| Console 出現 `ERR_NAME_NOT_RESOLVED` | 伺服器網址已失效。最常見是 cloudflared 重開後網址變了：用新網址覆蓋，兩邊都要。 |
| 對方看到 `unexpected response code 503` | cloudflared 免費通道不穩或掛了，改用 Render。 |
| 「已連線，等朋友加入」但朋友明明連上了 | 兩邊房間代碼不一樣（注意大小寫），或朋友還沒重新整理影片頁。 |
| 綠色但沒有同步 | 按 F12 看 Console 有沒有錯誤；確認兩邊在同一部影片；先在任一邊按 Alt+S（iPhone 按 ↻）。 |
| 被遠端播放時沒動作（iOS） | 被瀏覽器擋住自動播放，在頁面上點一下。 |
| Render 一開始連不上 | 免費方案休眠中，等 30～50 秒讓它喚醒。 |
| iPhone 腳本裝了沒反應 | 檔名是不是被改掉了（必須是 `.user.js`）；舊版 `iqiyi-sync.user.js` 要刪掉，避免兩支同時執行。 |
| 愛奇藝改版後失效 | 多半是播放器結構變了，`<video>` 沒被抓到，需要調整 `main.js` / 腳本的偵測方式。 |

## 安全性

### 你需要知道的基本事實

- **房間代碼就是門**：知道伺服器網址和房間代碼的人都能加入並控制播放。代碼請取長一點、不好猜的，例如 `dango-9x7k-movie`，不要用 `room1`。伺服器**強制至少 8 個字元**。
- 房間內**任何人**都能暫停或拖進度，也能把大家導向另一部影片，人多時先講好誰來操作。
- 伺服器只轉發很小的文字訊息（動作、秒數、影片網址），不經手影片內容，也不儲存帳號資料。日誌裡只會看到房間代碼雜湊後的前 6 碼，不會記錄代碼本身。
- 每個人都需要自己的平台帳號，並自行遵守各平台的使用條款。

### 已經內建的防護

| 項目 | 做法 |
|---|---|
| 只允許加密連線 | 擴充套件與 iPhone 腳本只接受 `wss://`；`ws://` 只能連 localhost（測試用） |
| 自動跳轉有白名單 | 只會跳到 https 的真正影片頁（YouTube `/watch?v=`、Netflix `/watch/數字`、愛奇藝 `/play` 或 `/v_`），不會被導向登出、帳號設定或其他網址 |
| 伺服器只轉發驗證過的欄位 | 訊息類型限 play / pause / nav / request；時間必須是合理數字；網址必須是 https；多餘欄位一律丟棄 |
| 擴充套件背景程式再驗證一次 | 網頁上的其他腳本（廣告、追蹤碼）和擴充套件共用同一環境，背景程式送出與收到的訊息都會過濾 |
| 頁面與擴充套件之間用私有通道 | `main.js` 與 `bridge.js` 用頁面載入最初建立的 MessageChannel 傳話，網頁上的其他腳本無法偷聽或偽造 |
| 跳轉網址不帶多餘參數 | 送出與收到的影片網址都重組成只含影片 ID 的形式，不會外流追蹤參數 |
| 防止猜房間代碼 | 每條連線只能加入一次，失敗即斷線；每個 IP 每 10 分鐘最多加入 30 次 |
| 來源白名單 | 預設只允許 Chrome 擴充套件、愛奇藝網頁與伺服器自己的網頁連線 |
| 訊息大小與頻率限制 | 單則訊息上限 4KB；每 10 秒超過 60 則直接斷線 |
| 連線數上限 | 每個房間最多 20 條連線、每個 IP 同時最多 20 條、全伺服器最多 300 條；連上後 10 秒內沒加入房間就斷線；定期清除死連線 |
| 不能中途換房間 | 加入後再送 join 會被忽略 |
| 網頁版安全標頭 | `X-Frame-Options: DENY`（防被嵌入別的網站）、`nosniff`、`Referrer-Policy`；只提供首頁與 `/healthz`，其他路徑一律 404 |
| 依賴套件 | 附 `package-lock.json`，`npm audit` 目前 0 個已知漏洞 |

### 可選設定（Render → Environment）

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `MIN_ROOM_LEN` | `8` | 房間代碼最短長度 |
| `MAX_PER_ROOM` | `20` | 每個房間最多連線數 |
| `MAX_CONNECTIONS` | `300` | 全伺服器連線上限 |
| `MAX_PER_IP` | `20` | 每個 IP 同時最多幾條連線，防止一個人佔滿全部名額。同一個網路的家人共用這個數字（每個分頁約 1～2 條） |
| `ALLOWED_ORIGINS` | Chrome 擴充 + 愛奇藝 | 只允許指定來源連線，逗號分隔、可用 `*`。預設：`chrome-extension://*,https://*.iqiyi.com,https://*.iq.com,https://iqiyi.com,https://iq.com`（伺服器自己的 YouTube 網頁版永遠允許）。**等所有人都換成固定 ID 的新版擴充套件後**，建議設成 `chrome-extension://lkfcgbmfbfadebnadmochcppblfhoijm,https://*.iqiyi.com,https://*.iq.com,https://iqiyi.com,https://iq.com`。設成 `*` 代表完全不檢查（不建議）。沒有 Origin 的程式或其他網站的連線都會被拒絕 |
| `PROXY_HOPS` | `0` | 前面有幾層代理。**部署在 Render 請設 `1`**，伺服器才拿得到每個人的真實 IP；不設的話所有人會被當成同一個 IP，共用下面的加入次數 |
| `JOIN_LIMIT` | `30` | 每個 IP 在時間窗內最多加入幾次（防止一直開新連線猜房間代碼） |
| `JOIN_WINDOW_MIN` | `10` | 上面的時間窗，單位分鐘 |
| `REJOIN_GRACE_SEC` | `10` | 同一個人斷線後幾秒內重連視為沒離開（換頁、重新整理）。太短：換頁慢時仍會被拉回；太長：朋友真的離開後要等比較久才顯示 |

> `ALLOWED_ORIGINS` 擋的是「別的網站上的腳本」，不是惡意的人用自己寫的程式連線（Origin 可以偽造），所以它是輔助，真正的門還是房間代碼。

### 已知限制（沒辦法完全解決的部分）

- **iPhone 腳本的設定存放位置取決於腳本管理器**：支援 `GM.getValue` / `GM.setValue`（例如 Userscripts）時存在腳本自己的空間，網站讀不到；不支援時才退回愛奇藝網站的 localStorage，網站上的其他腳本理論上讀得到。電腦版擴充套件存在擴充套件自己的儲存空間，沒有這個問題。如果在意，定期換一個新的房間代碼即可。
- 擴充套件的頁面部分（`main.js`）必須在網頁環境執行（Netflix 需要）。傳話已改用私有通道，但網頁上的腳本仍可以直接操作 `<video>`（例如暫停），這會被當成你的操作同步出去。目前靠白名單與過濾把能做的事限制在「同步播放」與「跳到影片頁」。
- 這份程式沒有帳號密碼或登入機制，也沒有端對端加密：伺服器看得到房間代碼和影片網址。因此不要使用不信任的人架設的伺服器。
- 臨時通道（cloudflared）的網址等於公開入口，只建議短時間測試用。

## 更新

- 改了 `extension/` 裡的檔案：到 `chrome://extensions` 按重新載入，再重新整理影片頁。
- 改了 `ios/` 腳本：覆蓋 Userscripts 資料夾裡的同名檔案，再重新整理頁面。
- 改了 `server/`：重新部署（Render 在 push 到 GitHub 後會自動重新部署）。Build Command 建議用 `npm ci`（依照 `package-lock.json` 安裝固定版本）。

### 從舊版升級到有安全強化的版本

1. 伺服器、電腦擴充套件、iPhone 腳本**三個都要更新**；只更新伺服器的話，舊版客戶端仍可運作，但不會有客戶端那一層的驗證。
2. 房間代碼不足 8 個字元的，要換成更長的。連上後左上角會顯示「房間代碼至少 8 個字元」。
3. 伺服器網址一定要是 `wss://`（Render 與 cloudflared 的網址換成 `wss://` 開頭即可）。

- `manifest.json` 加入 `key`，擴充套件 ID 固定為 `lkfcgbmfbfadebnadmochcppblfhoijm`，伺服器可以只允許這個 ID。**ID 改變後原本的設定會清空，更新後要重新填伺服器網址和房間代碼**

- 跳轉網址只傳影片 ID 需要的部分（YouTube 只留 `v`，Netflix / 愛奇藝只留路徑），收到時也重組
- 換頁重連時：自己點進新影片才推給對方；跟著對方跳過來的頁面不推回去，避免互推
- 重新整理、跟著對方跳過來、第一次加入時，會自動向對方要目前進度（之前電腦版要手動按 Alt+S）
- 修正：換頁重連時自己選的新影片原本永遠推不出去（沒有跟隨記號時被誤判成「跟隨而來」）
- 修正：重新整理後播放器自己跳回上次位置、自動播放，會被當成你的操作送出，反而把朋友拉到你的進度。現在頁面剛載入時先不送出自己的播放事件，等對完朋友的進度（最多 3 秒），或確認房裡只有自己後才恢復；最久 8 秒一定恢復。Alt+S 不受影響
- 伺服器拒絕加入時不自動重連，標籤保留伺服器給的原因；房間已滿時 30 秒後再試

**iPhone 腳本**

- 只在 `https://` 頁面執行；peer id 改用密碼學亂數
- 套用同樣的換頁重連規則：跟著對方過來或同一部影片重新整理會要進度，自己選新影片則推給對方
- 伺服器拒絕加入時不自動重連
- 伺服器網址、房間代碼、peer id 改存在腳本自己的空間（`GM.getValue` / `GM.setValue`），愛奇藝網頁上的其他腳本讀不到；舊版存在 localStorage 的設定會自動搬過去並刪除。腳本管理器不支援時照舊使用 localStorage
